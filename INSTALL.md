# Установка

Приложение состоит из двух частей:

- **Сервер синхронизации** — хранит общую базу. Ставится на один компьютер, который включён, когда нужно обменяться данными.
- **Приложение** — на каждом устройстве. Работает и без сервера; с сервером данные на всех устройствах одинаковые.

## 1. Сервер (база данных)

Нужен [Node.js](https://nodejs.org) версии 24 или новее. Больше ничего ставить не надо: база — один файл SQLite.

Готовая папка с сервером собирается командой `npm run dist:server` и появляется в `release/finanse-server/` (и архивом `release/finanse-server.zip`). Её можно перенести на любой компьютер.

### Linux

```sh
cd release/finanse-server
./install.sh
```

Установщик копирует сервер в `~/.local/share/finanse-server`, создаёт службу пользователя systemd и запускает её. В конце он печатает **адрес** и **ключ доступа** — они понадобятся на каждом устройстве.

- Состояние: `systemctl --user status finanse-server`
- Показать ключ ещё раз: `FINANSE_DATA=~/.local/share/finanse-server/data node ~/.local/share/finanse-server/server.mjs --token`
- Другой порт: `FINANSE_PORT=9000 ./install.sh`
- Убрать службу: `./install.sh --uninstall` (база остаётся)

Если другие устройства не видят сервер, откройте порт 8787 в брандмауэре.

### Windows

В папке `finanse-server` откройте PowerShell и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1
```

Сервер ставится в `%LOCALAPPDATA%\finanse-server` и запускается при входе в систему. Чтобы установщик сам открыл порт в брандмауэре, запустите PowerShell от имени администратора. Убрать автозапуск: тот же файл с ключом `-Uninstall`.

Установщик для Windows написан, но на Windows не запускался — проверить его было негде.

### Где лежат данные

В папке `data` рядом с сервером: `finanse.sqlite` — база, `config.json` — ключ доступа. Чтобы сделать копию базы, скопируйте всю папку `data`, пока сервер остановлен.

### Windows-сервер в интернете (VPS)

Для сервера, доступного из интернета, есть отдельный установщик. Он ставит всё сразу: Node.js (если его нет), сервер с базой, само приложение и HTTPS — и запускает это в фоне при старте Windows, без входа в систему и без окон.

1. Скачайте проект на сервер: на странице репозитория **Code → Download ZIP** и распакуйте. Подойдёт и архив `release/finanse-server.zip`, собранный командой `npm run dist:server`.
2. Откройте файл **`Finanse.cmd`** двойным щелчком. Он сам запросит права администратора. Если Windows покажет предупреждение о неизвестном издателе, нажмите «Подробнее» → «Выполнить в любом случае».
3. В меню выберите **1 — Установить или обновить** и режим:
   - **Только база для приложений** — сервер отвечает на `http://IP:8787` и только обменивается данными с установленными приложениями. Порты 80 и 443 не нужны, поэтому режим подходит, если на сервере уже работает сайт. Порт 8787 нужно открыть в панели управления VPS.
   - **База и приложение в браузере по HTTPS** — нужны свободные порты 80 и 443.

Меню:

| Пункт | Что делает |
|---|---|
| 1. Установить или обновить | ставит или обновляет всё; база и ключ сохраняются |
| 2. Запустить | запускает сервер в фоне |
| 3. Остановить | останавливает до следующей перезагрузки |
| 4. Показать адрес и ключ | то, что вводится на устройствах |
| 5. Удалить службы | убирает автозапуск и правила брандмауэра, база остаётся |
| 6. Диагностика | кто занимает порты, состояние задач, последние строки журналов |

После установки окно можно закрыть: сервер работает в фоне и сам запускается вместе с Windows. Адрес, ключ доступа и **строка подключения** (адрес и ключ одной строкой) сохраняются в `C:\ProgramData\finanse-server\connection.txt`.

В режиме «только база» соединение не шифруется: ключ и данные идут по интернету открытым текстом.

- **Адрес.** Без своего домена используется бесплатное имя `sslip.io`, которое указывает на IP сервера; сертификат выпускает Let's Encrypt. Свой домен установщик спросит сам.
- **Порты.** В панели управления VPS должны быть открыты 80 и 443.
- **Если на сервере уже есть сайт.** Тогда порты 80 и 443 заняты им, и отдельный HTTPS поставить нельзя. Установщик это заметит и предложит простой режим: адрес вида `http://IP:8787` без шифрования (порт 8787 нужно открыть в панели VPS). В этом режиме приложение на телефон не устанавливается и системные уведомления не работают. Чтобы получить HTTPS, «Финансы» нужно подключить через веб-сервер существующего сайта — правилом, которое пересылает запросы на `http://127.0.0.1:8787`.
- **Журналы.** `C:\ProgramData\finanse-server\server.log` и `caddy\caddy.log`.
- **Свежая версия приложения.** В репозитории лежит готовая сборка в `server/web`. После изменений в приложении её нужно обновить командой `npm run dist:server` и закоммитить.

По такому адресу приложение работает по HTTPS, поэтому на телефоне его можно установить на главный экран как обычное приложение, и системные уведомления работают.

Этот установщик проверен только частично: синтаксис, настройки HTTPS-прокси и работа сервера за ним — на Linux. На самой Windows он не запускался.

## 2. Подключение устройств

На каждом устройстве в приложении: **Ещё → Синхронизация между устройствами** → адрес сервера (например, `http://192.168.1.10:8787`) и ключ доступа → **Подключить**.

Чтобы не набирать ключ на телефоне, можно вставить в поле адреса строку подключения целиком — `адрес#ключ`. Установщик для Windows показывает её сам; её удобно переслать себе в мессенджере.

Дальше обмен идёт сам: после каждой правки, раз в минуту и при возвращении в приложение. Если одну запись изменили на двух устройствах, остаётся более поздняя правка.

Первое устройство отправляет на сервер всё, что в нём уже есть. Остальные получают эти данные при подключении, а их собственные записи добавляются к общим.

## 3. Приложение на компьютер

### Linux

```sh
npm run dist:linux
```

Получается `release/Finanse-1.0.0-linux-x86_64.AppImage` — один файл, который запускается без установки (`chmod +x` и двойной щелчок).

### Windows

Установщик `.exe` собирается только на Windows:

```sh
npm run dist:win
```

Либо автоматически на GitHub: после отправки метки версии (`git tag v1.0.0 && git push --tags`) во вкладке Actions появятся готовые файлы для Windows и Linux и архив с сервером.

### Важно про данные

У установленной программы своё хранилище, отдельное от браузера. Чтобы перенести данные из браузера, подключите оба к серверу или воспользуйтесь экспортом и импортом на вкладке «Ещё».

## 4. Телефон (Android)

### Приложение

Приложение для Android собирается на GitHub — на компьютере для этого ничего ставить не нужно:

1. Отправьте изменения в репозиторий.
2. На странице репозитория: **Actions → «Сборка установщиков» → Run workflow**.
3. Когда сборка закончится, откройте её и в разделе **Artifacts** скачайте `finanse-Android` — внутри `Finanse.apk`. Там же лежат установщик для Windows, программа для Linux и архив с сервером.
4. Перенесите `Finanse.apk` на телефон и откройте. Android попросит разрешить установку из этого источника.

Что в приложении для телефона по-другому:

- напоминания о платежах, взносах и льготном периоде приходят и при закрытом приложении — в девять утра в нужный день;
- экспорт копии открывает системное окно «Поделиться»: файл можно сохранить или отправить себе;
- кнопка «Назад» закрывает открытое окно;
- к серверу можно подключаться по обычному HTTP.

Обновление ставится поверх старой версии, данные сохраняются: все сборки подписаны одним ключом, который лежит в репозитории (`android/app/finanse.p12`). Это ключ личного приложения, а не секрет: для публикации в Google Play понадобился бы отдельный.

Приложение для Android и его сборка на GitHub написаны, но ни разу не запускались: на компьютере, где шла разработка, нет Android-инструментов.

### Без установки

Если сервер раздаёт приложение (домашний сервер или режим с HTTPS), его адрес можно открыть в браузере телефона. По обычному HTTP при этом не работают установка на главный экран и системные уведомления.

## 5. Доступ не из дома

Самый простой способ — сервер на VPS с HTTPS (раздел про Windows-сервер выше).

Домашний сервер работает по обычному HTTP и рассчитан на домашнюю сеть. Чтобы пользоваться им снаружи, нужна частная сеть между устройствами (VPN, например Tailscale или WireGuard) — тогда адресом сервера станет его адрес в этой сети. Выставлять порт сервера в интернет напрямую не стоит: соединение не шифруется, а ключ даёт полный доступ к данным.
